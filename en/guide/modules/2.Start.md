## 1. Preparing the Environment

### 1.1. What You'll Need

To write module code, you will need a text editor. VS Code is the best choice because it has a convenient extension for working with the module documentation.

### 1.2. Where Modules Are Stored

All standard modules are stored in the game's resources. It is not recommended to delete them, but you can disable them.

All user modules are stored in the `Modules` folder in the game's root directory.

All `.lua` documentation for modules is stored in the `ModuleAPI` folder in the game's root directory.

### 1.3. Setting Up VS Code

#### Step 1. Download VS Code

You can download VS Code here: [code.visualstudio.com](https://code.visualstudio.com/)

#### Step 2. Install the Lua extension

You can install the Lua extension here: [marketplace.visualstudio.com/sumneko.lua](https://marketplace.visualstudio.com/items?itemName=sumneko.lua)

## 2. Creating and Debugging Your First Module

### 2.1. What We're Going to Build

It's time to create your first module, but instead of starting with complicated mechanics, we'll begin with the most useful early skill: how to quickly check whether the module loaded at all, how it reloads, and where to look for its logs.

We'll create a simple module called `Hello Debug`, and use it to learn how to:

- create a module through the in-game GUI
- find the module folder and understand which files the game creates
- run the module on a custom server
- use auto-reload when files change
- view `print()` messages in the in-game console
- display debug information directly on the screen

### 2.2. Creating a Module Through the Menu

You can create a module using the "**Create**" button in the modules menu.

![](../../../images/create_module_1.png)

For the first example, `Hello Debug` is a convenient name.

The "**Is Reflex**" flag creates a module with a server-side part. You do not need it for your first module. See: [Tech.md / Reflex flag](./5.Tech.md#reflex-flag)

We also will not add any tags to the module. For more about tags, see: [Tech.md / Module tags](./5.Tech.md#module-tags)

![](../../../images/create_module_2.png)

### 2.3. Where the Module Lives and What the Game Creates

After creation, the module will appear in the following folder:

```text
/[Game Folder]/Modules/Hello Debug/
```

You can open this folder from the game using the "**Folder**" button.

Inside, you will already see `module.json`, `scripts/main.lua`, and service files for VS Code. For more about the structure, see: [Tech.md / Module folder structure](./5.Tech.md#module-folder-structure)

By default, `scripts/main.lua` already contains the simplest possible code:

```lua
print("Hello world!")
```

![](../../../images/new_module_folder.png)

### 2.4. How to Test a Module on a Custom Server

For debugging modules, the most convenient option is to use a custom server from the game's main menu. It makes it easier to quickly load into a map, restart a round, and verify changes without matchmaking.

Important: modules do not run in the main menu. There you can only open the modules menu, enable the module you need, and start the server. The Lua code itself will start working only after the game session has loaded.

![](../../../images/create_custom_server.png)

If you need a separate guide not only for launching but also for administering a custom server, you can use this instruction:

- [Custom server administration guide](https://www.youtube.com/watch?v=6hbD3Ekx0AE)

### 2.5. How to Open the Console and Find Module Logs

By default, the console opens with the tilde key `` ` ``. If it does not work for you, check the game settings: the console key may have been changed.

After opening the console, type the module name in the console search box, for example `Hello Debug`. That way, you will quickly see all messages related specifically to this module: your `print()` output, Lua errors, and so on.

![](../../../images/console_search.png)

### 2.6. Writing the First Log Message

Open the module folder and replace the contents of `scripts/main.lua` with this example:

```lua
local first_tick = false

print("main.lua loaded")

local function Tick()
    if first_tick then
        return
    end

    print("First tick")
    first_tick = true
end

Events:On("Tick", Tick)
```

The game watches the files inside the module folder. When you save changes, the module **reloads automatically**.

![](../../../images/module_autoreload.png)

What this code does:

- the first `print()` runs when the `main.lua` file is loaded
- the second `print()` runs on the first frame after the module starts (`Tick` is called once at the beginning of every frame)

The `print()` method outputs a message to the in-game console. This is the simplest way to confirm whether the code path you care about is actually running.

![](../../../images/module_debug_1.png)

### 2.7. Debugging with ImGui

During debugging, it is useful not only to write to the console but also to display information directly on the screen. For that, [ImGui](../../api/ImGui.md#imgui) is very convenient.

If you want quick debug text in the corner of the screen, you can use [ImGui:DrawDebugText](../../api/ImGui.md#drawdebugtext):

```lua
local function Tick()
    ImGui:DrawDebugText("[Hello Debug] Current tick: " .. tostring(Time.Tick))
end

Events:On("Tick", Tick)
```

![](../../../images/module_debug_2.png)

This option is useful when you want to quickly check:

- whether the handler is being called
- whether the value changes from frame to frame
- what the module's current internal state is

If you need not just a debug message at the edge of the screen, but text in a specific region, use [ImGui:DrawText](../../api/ImGui.md#drawtext).

For example:

```lua
local function Tick()
    ImGui:DrawText(
        "[Hello Debug] Current tick: " .. tostring(Time.Tick),
        Rect(40, 240, 500, 40),
        16,
        Color(1, 1, 1, 1),
        TextAnchor.MiddleLeft
    )
end

Events:On("Tick", Tick)
```

This example draws normal text in the upper-left area of the screen.

![](../../../images/module_debug_3.png)

In practice, the difference is simple:

- [`ImGui:DrawDebugText`](../../api/ImGui.md#drawdebugtext) is convenient for quick temporary debugging
- [`ImGui:DrawText`](../../api/ImGui.md#drawtext) is convenient when you want to choose the text position, size, and color yourself

## 3. Cloning and Extending a Built-in Module

In this section, we will make a clone of the standard minimap module and extend it by adding the player's coordinates below the minimap, next to the current zone name.

### 3.1. Creating a Clone of a Built-in Module

Select a module from the list and click the "**Fork**" button on it.

![](../../../images/fork_module.png)

Then enter a name for the new module and click "**Fork module**".

![](../../../images/fork_module_2.png)

This creates a new user module that clones the full structure and resources of the original one.

### 3.2. Resolving the Conflict

At this point, we have two running modules that both implement the minimap, so the old one should be disabled so it does not get in the way.

For more about conflicts and module tags, see: [Tech.md / Module tags](./5.Tech.md#module-tags)

![](../../../images/module_conflict_1.png)

After disabling it, the conflict disappears.

![](../../../images/module_conflict_2.png)

### 3.3. Launching and Checking the New Module

Launch the game and make sure the new minimap module works correctly and has inherited all functionality from the original.

![](../../../images/work_minimap.png)

But we do not like how zones are displayed under the minimap: we want to add the player's coordinates there as well. Let's change that.

Copy this path and open it in VS Code.

### 3.4. Step-by-Step Editing

Now the folder for the user module is available at:

```text
/[Game Folder]/Modules/[New Module Name]/
```

You can open it from the game using the "**Folder**" button.

#### Step 1. Finding the Function

In `scripts/main.lua`, find the `UpdateZoneText()` function that is responsible for displaying the zone name under the minimap.

```lua
local function UpdateZoneText()
    local zones = MapInfo:GetZones(Cameras.Main.Position)
    local text = ''
    if zones.Length > 0 then
        text = zones[1]
    end

    text = UI:ToUpperInvariant(text)

    if coordinatesTextSmall then
        coordinatesTextSmall.text = text
    end

    if coordinatesTextFullscreen then
        coordinatesTextFullscreen.text = text
    end
end
```

Here, the code gets the list of zones where the player's main camera is located, takes the first zone from that list, and displays it.

#### Step 2. Changing the Function

Let's change the function so it displays the player's coordinates before the zone name.

```diff
local function UpdateZoneText()
    local zones = MapInfo:GetZones(Cameras.Main.Position)
    local text = ''
    if zones.Length > 0 then
        text = zones[1]
    end

-    text = UI:ToUpperInvariant(text)
+    local cord_text = 'Pos: ' .. tostring(LocalAgentPos) .. ' '
+    text = cord_text .. UI:ToUpperInvariant(text)

    if coordinatesTextSmall then
        coordinatesTextSmall.text = text
    end

    if coordinatesTextFullscreen then
        coordinatesTextFullscreen.text = text
    end
end
```

After the change, the function will look like this:

```lua
local function UpdateZoneText()
    local zones = MapInfo:GetZones(Cameras.Main.Position)
    local text = ''
    if zones.Length > 0 then
        text = zones[1]
    end

    local cord_text = 'Pos: ' .. tostring(LocalAgentPos) .. ' '
    text = cord_text .. UI:ToUpperInvariant(text)

    if coordinatesTextSmall then
        coordinatesTextSmall.text = text
    end

    if coordinatesTextFullscreen then
        coordinatesTextFullscreen.text = text
    end
end
```

Save the file.

After entering the game, you will see that the minimap has changed.
