## 1. How a Reflex Module Works

For this aim module, we need a module with the `IsReflex` flag. Only one module with the `Reflex` tag can be enabled at a time. For more about the flag and module conflicts, see: [Tech.md / Reflex flag](./5.Tech.md#reflex-flag).

A Reflex module has two separate Lua parts:

- `scripts/main.lua` runs on the client and handles input, UI, and local settings
- `scripts/server.lua` runs on the server and controls aiming and shooting for the local agent

When a player joins the map, the code from `scripts/server.lua` is sent to the server. The server-side part can only use the API available there, but regular `print()` output is still available for debugging.

The client and server exchange tables through [`Network`](../../api/Network.md#network): [`Network:SendTable(table)`](../../api/Network.md#sendtable) sends state to the other side, and [`Network:OnTableReceived(callback)`](../../api/Network.md#ontablereceived) registers a handler for incoming data.

These tables support `string`, `number`, `boolean`, `nil`, and nested tables. Values of other types are silently ignored.

To run code regularly, use [`Scheduler`](../../api/Scheduler.md#scheduler). On the client side, [`Scheduler:OnFrame(callback)`](../../api/Scheduler.md#onframe) is available, and in the server side of a Reflex module, use [`Scheduler:OnTick(callback)`](../../api/Scheduler.md#ontick).

<a id="2-result"></a>
## 2. What We Are Going to Build

The finished module will:

- look for a living visible enemy inside a sector in front of the crosshair
- choose the enemy closest to the center of the crosshair
- aim at the head for `SniperRifle` and `Revolver`, and at the body for other weapons
- get possible trajectories through [`FirearmItem:GetPredictedHits()`](../../api/Item.md#getpredictedhits)
- fire only if at least two predicted trajectories hit the selected target
- toggle the mode with the `V` key and remember it separately for each weapon
- display the current mode at the bottom of the screen

The threshold of two successful trajectories is just an example. The higher it is, the longer the aim waits for a favorable spread and the less often it fires.

<a id="4-server-aim"></a>
## 4. Server-Side Aim Logic

All code in this section goes into `scripts/server.lua`.

### 4.1. State and Core Settings

Add the first block to `scripts/server.lua`: references to the local agent, the search angle, the successful trajectory threshold, and the state that will later arrive from the client:

```lua
---@type Agent | nil
local LocalAgent = nil

local HALF_FOV_COS = math.cos(12 * math.pi / 180)
local MIN_SUCCESSFUL_PREDICTIONS = 2

local NetworkState = {
    SniperMode = false
}

Network:OnTableReceived(function(state)
    NetworkState = state
end)

local function IsAgentAlive(agent)
    return agent and agent.Health and agent.Health.IsAlive == true
end
```

`HALF_FOV_COS` controls how close to the center of the crosshair a target must be before the aim starts considering it. In simpler terms, it is the radius of the search zone in front of the player.

`NetworkState.SniperMode` is `false` for now. Once we add the client-side part, the server will start receiving the current value through [`Network:OnTableReceived`](../../api/Network.md#ontablereceived).

You can check whether an agent is alive through [`Health.IsAlive`](../../api/Agent.md#health).

### 4.2. Finding a Target Near the Crosshair

Next, add these two functions to `scripts/server.lua`:

```lua
local function GetAimDot(target, firePos)
    local toTarget = target.Aim.Position - firePos
    toTarget = toTarget:Normalize()

    return LocalAgent.Aim.Direction:Dot(toTarget)
end

local function FindBestTarget(firePos)
    local enemies = Agents:GetEnemies()
    local bestTarget = nil
    local bestDot = HALF_FOV_COS

    for i = 1, enemies.Length do
        local enemy = enemies[i]

        if IsAgentAlive(enemy) and enemy.IsVisible then
            local dot = GetAimDot(enemy, firePos)

            if dot > bestDot then
                bestDot = dot
                bestTarget = enemy
            end
        end
    end

    return bestTarget
end
```

[`Agents:GetEnemies()`](../../api/Agent.md#getenemies) returns an array of enemies relative to the local team. In Lua, loops over API arrays start at `1`, so the loop runs from `1` through `Length` inclusive.

`GetAimDot` builds a normalized direction toward the target and compares it with [`Aim.Direction`](../../api/Agent.md#aim) through [`Vector3:Dot`](../../api/Structs.md#dot-2). The closer the result is to `1`, the closer the target is to the center of the crosshair. The `enemy.IsVisible` check prevents the module from selecting agents hidden from the local team.

### 4.3. Choosing the Hitbox

Below that, add functions to find the hitbox for the required body part:

```lua
local function FindHitboxByBodyPart(target, bodyPart)
    local hitboxes = target:GetHitboxes()

    for i = 1, hitboxes.Length do
        local hitbox = hitboxes[i]

        if hitbox and hitbox.BodyPart == bodyPart then
            return hitbox
        end
    end

    return nil
end

local function GetAimHitbox(target)
    if NetworkState.SniperMode then
        return FindHitboxByBodyPart(target, EHitboxBodyPart.Head)
    end

    return FindHitboxByBodyPart(target, EHitboxBodyPart.Body)
        or FindHitboxByBodyPart(target, EHitboxBodyPart.Head)
end
```

[`Agent:GetHitboxes()`](../../api/Agent.md#gethitboxes) returns the agent's hitboxes, and [`Hitbox.BodyPart`](../../api/Agent.md#hitbox) tells you which body part each one belongs to.

In sniper mode, the function returns only the head. In regular mode, it looks for the body first and falls back to the head if no body hitbox is found.

<a id="5-predicted-hits"></a>
## 5. How Predicted Shots Work

### 5.1. Prediction Mechanics

Weapon spread means a future shot cannot be described in advance by a single line. So on each server tick, the server takes the current [`Aim.Position`](../../api/Agent.md#aim), [`Aim.Direction`](../../api/Agent.md#aim), and weapon inaccuracy, then calculates several random trajectories for possible shots. In the current implementation, it calculates ten variants, but in code you should rely on `Length` instead of hardcoding that number.

[`FirearmItem:GetPredictedHits()`](../../api/Item.md#getpredictedhits) returns `Array<Array<HitscanHit>>`:

- the outer array contains possible trajectories
- each inner array contains the sequence of hits for one trajectory
- a single hit is described by a [`HitscanHit`](../../api/Item.md#hitscanhit) object
- if a bullet penetrates a surface, the same trajectory can contain further hits after the penetration

When the weapon actually fires, the server chooses one of the trajectories calculated in advance. So you cannot know the single future hit point or choose a specific trajectory. But you can estimate the chance: for example, `2` successful variants out of `10` means that two possible shot directions intersect the target.

Each [`HitscanHit`](../../api/Item.md#hitscanhit) also has `EntryPoint`, `EntryPower`, `ExitPower`, and `HasExited`. A more advanced aim can use them to account for the impact point and the remaining power after penetration. For this tutorial, it is enough to know whether the trajectory intersects the target's hitbox at all.

### 5.2. Counting Successful Trajectories

Now add this function to `scripts/server.lua`, which checks every hit in every predicted trajectory:

```lua
local function CountPredictedHitsOnTarget(firearm, target)
    local predictedShots = firearm:GetPredictedHits()
    local successfulShots = 0

    for shotIndex = 1, predictedShots.Length do
        local hits = predictedShots[shotIndex]

        for hitIndex = 1, hits.Length do
            local hit = hits[hitIndex]
            local hitbox = hit.Hitbox

            if hitbox and hitbox.Agent == target then
                successfulShots = successfulShots + 1
                break
            end
        end
    end

    return successfulShots
end
```

[`HitscanHit.Hitbox`](../../api/Item.md#hitscanhit) can be `nil`, for example when the shot hits map geometry. If the hitbox exists, [`Hitbox.Agent`](../../api/Agent.md#hitbox) lets you verify its owner.

We inspect the full inner array rather than only the first hit so the target still counts even if it stands behind a penetrable surface. After the first hit on the selected enemy, the code uses `break` so one trajectory is counted only once.

Both loops run from `1` to `Length`: the outer loop iterates predicted trajectories, and the inner one iterates hits inside a single trajectory.

### 5.3. Server Tick

All helper functions are ready. At the end of `scripts/server.lua`, add the main handler:

```lua
local function Tick()
    LocalAgent = Agents:GetLocalAgent()

    if not IsAgentAlive(LocalAgent) then
        return
    end

    local currentItem = LocalAgent.Inventory.CurrentItem

    if not currentItem or not currentItem.IsFirearm then
        LocalAgent.Aim:ResetAimTarget()
        return
    end

    local firearm = currentItem.AsFirearmItem
    local firePos = LocalAgent.Aim.Position
    local target = FindBestTarget(firePos)

    if not target then
        LocalAgent.Aim:ResetAimTarget()
        return
    end

    local hitbox = GetAimHitbox(target)

    if not hitbox then
        LocalAgent.Aim:ResetAimTarget()
        return
    end

    LocalAgent.Aim:SetAimTarget(hitbox.Position, target)

    local successfulShots = CountPredictedHitsOnTarget(firearm, target)
    local canFire = successfulShots >= MIN_SUCCESSFUL_PREDICTIONS
        and firearm.HasAmmo
        and not firearm.IsReloading

    AgentInput:SetButtonState(EInputButton.Fire, canFire)
end

Scheduler:OnTick(Tick)
```

On every server tick, the code:

1. gets the local agent through [`Agents:GetLocalAgent()`](../../api/Agent.md#getlocalagent)
2. reads [`Inventory.CurrentItem`](../../api/Agent.md#inventory) and converts the firearm through [`Item.AsFirearmItem`](../../api/Item.md#item)
3. chooses a target and a hitbox
4. sets the aim point through [`Aim:SetAimTarget`](../../api/Agent.md#setaimtarget)
5. counts successful predicted trajectories
6. sets the fire button state through [`AgentInput:SetButtonState`](../../api/Agent.md#setbuttonstate): presses it if the threshold is reached and the weapon is ready, otherwise releases it

If there is no suitable target or weapon, [`Aim:ResetAimTarget()`](../../api/Agent.md#resetaimtarget) returns control of the aim to the player.

<a id="6-client"></a>
## 6. Client-Side Settings

Now let's configure `scripts/main.lua`.

### 6.1. Toggle Key

Create `inputs.json` in the root of the module and put this into it:

```json
{
  "Actions": [
    {
      "Name": "ToggleSniperMode",
      "Type": "Button",
      "Binding": {
        "Path": "<Keyboard>/v"
      }
    }
  ]
}
```

Custom module actions are declared in `inputs.json` and then looked up by name through [`InputActions:FindAction`](../../api/InputAction.md#findaction). For the full format and all fields, see: [Tech.md / inputs.json file](./5.Tech.md#inputsjson-file).

### 6.2. Client State

At the top of `scripts/main.lua`, add:

```lua
---@type FirearmItem | nil
local CurrentFirearm = nil

local ToggleSniperModeAction = nil
local NetworkState = {
    SniperMode = false
}

local function GetWeaponName(firearm)
    return string.gsub(firearm.Name, " ", "")
end

local function GetDefaultSniperMode(weaponName)
    return weaponName == "SniperRifle" or weaponName == "Revolver"
end
```

`CurrentFirearm` stores the current weapon. Spaces are removed from [`Item.Name`](../../api/Item.md#item) to get a stable settings key. For the sniper rifle and the revolver, head aim is enabled by default.

### 6.3. Sending and Saving the Mode

Next, add these functions to `scripts/main.lua` to store the selected mode separately for each weapon, restore it on switch, and send the current state to the server:

```lua
local function SendNetworkState()
    Network:SendTable(NetworkState)
end

local function SaveSniperModeForWeapon()
    if not CurrentFirearm then
        return
    end

    if not Storage.Weapons then
        Storage.Weapons = {}
    end

    local weaponName = GetWeaponName(CurrentFirearm)
    Storage.Weapons[weaponName] = NetworkState.SniperMode
end

local function LoadSniperModeForWeapon()
    if not CurrentFirearm then
        return
    end

    local weaponName = GetWeaponName(CurrentFirearm)
    local savedMode = Storage.Weapons and Storage.Weapons[weaponName]

    if savedMode ~= nil then
        NetworkState.SniperMode = savedMode
    else
        NetworkState.SniperMode = GetDefaultSniperMode(weaponName)
    end

    SendNetworkState()
end

local function ToggleSniperMode()
    if not CurrentFirearm then
        return
    end

    NetworkState.SniperMode = not NetworkState.SniperMode
    SaveSniperModeForWeapon()
    SendNetworkState()
end
```

`SaveSniperModeForWeapon()` writes the current `SniperMode` value into [`Storage`](../../api/Storage.md#storage) under the active weapon name, and `LoadSniperModeForWeapon()` reads it back. If there is no saved value yet, it falls back to the default from `GetDefaultSniperMode()`.

`ToggleSniperMode()` is used for manual switching: it flips the current state, saves it, and immediately calls `SendNetworkState()`. That function sends `NetworkState` to the server.

[`Storage`](../../api/Storage.md#storage) is loaded automatically when the module starts and saved automatically when it is disabled.

### 6.4. Tracking Weapon Changes

Also add this check for switching items to `scripts/main.lua`:

```lua
local function CheckFirearmChanged(localAgent)
    local currentItem = localAgent.Inventory.CurrentItem

    if currentItem and currentItem.IsFirearm then
        local firearm = currentItem.AsFirearmItem

        if not CurrentFirearm or firearm.Name ~= CurrentFirearm.Name then
            CurrentFirearm = firearm
            return true
        end
    elseif CurrentFirearm then
        CurrentFirearm = nil
        return true
    end

    return false
end
```

This function returns `true` only when the weapon actually changed. Because of that, reading `Storage` and sending the table happens when the player switches items, not on every frame.

### 6.5. Text at the Bottom of the Screen

Below the previous functions in `scripts/main.lua`, add the drawing function:

```lua
local function DrawSniperMode()
    if not CurrentFirearm then
        return
    end

    local text = "Sniper: off"

    if NetworkState.SniperMode then
        text = "Sniper: on"
    end

    ImGui:DrawText(
        text,
        Rect.new((Screen.Width * 0.5) - 100, Screen.Height - 80, 200, 30),
        20,
        Color.new(1.0, 1.0, 1.0, 1.0),
        TextAnchor.MiddleCenter)
end
```

[`ImGui:DrawText`](../../api/ImGui.md#drawtext) draws text inside the given [`Rect`](../../api/Structs.md#rect). The coordinates are calculated from [`Screen`](../../api/Environment.md#screen), so the label stays centered across different resolutions.

### 6.6. Client Frame and Subscriptions

Finally, add the last block to the end of `scripts/main.lua`:

```lua
local function Tick()
    local localAgent = Agents:GetLocalAgent()

    if not localAgent or not localAgent.Health.IsAlive then
        return
    end

    if CheckFirearmChanged(localAgent) and CurrentFirearm then
        LoadSniperModeForWeapon()
    end

    DrawSniperMode()
end

ToggleSniperModeAction = InputActions:FindAction("ToggleSniperMode")
ToggleSniperModeAction:OnPerformed(ToggleSniperMode)
Scheduler:OnFrame(Tick)
```

[`InputAction:OnPerformed`](../../api/InputAction.md#onperformed) triggers the mode switch when `V` is pressed.
[`Scheduler:OnFrame`](../../api/Scheduler.md#onframe) checks the weapon and draws the label every client frame.

The module is now ready: the client stores the selected mode and sends it to the server, while the server picks a target and presses fire only when enough predicted trajectories are suitable.
