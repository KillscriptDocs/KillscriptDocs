# Пишем свой аим в Reflex-модуле

В этой главе соберем простой аим, который выбирает ближайшего к прицелу видимого противника, наводится на нужную часть тела и стреляет только тогда, когда предсказанные траектории дают приемлемый шанс попадания.

<a id="1-reflex-details"></a>
## 1. Как устроен Reflex-модуль

Для аима нужен модуль с флагом `IsReflex`. Одновременно может быть включен только один модуль с тегом `Reflex`. Подробнее о флаге и конфликтах модулей: [Tech.md / Флаг Reflex](./5.Tech.md#флаг-reflex).

У Reflex-модуля две независимые Lua-части:

- `scripts/main.lua` выполняется на клиенте и отвечает за ввод, интерфейс и локальные настройки;
- `scripts/server.lua` выполняется на сервере и управляет прицеливанием и стрельбой локального агента.

При подключении игрока код `scripts/server.lua` отправляется на сервер. Серверная часть работает только через доступное ей API, но для отладки в ней можно использовать обычный `print()`.

Клиент и сервер обмениваются таблицами через [`Network`](../../api/Network.md#network): [`Network:SendTable(table)`](../../api/Network.md#sendtable) отправляет состояние противоположной стороне, а [`Network:OnTableReceived(callback)`](../../api/Network.md#ontablereceived) регистрирует обработчик входящих данных.

В таких таблицах поддерживаются `string`, `number`, `boolean`, `nil` и вложенные таблицы. Значения других типов молча игнорируются.

Для регулярного выполнения кода используется [`Scheduler`](../../api/Scheduler.md#scheduler). На клиенте доступен [`Scheduler:OnFrame(callback)`](../../api/Scheduler.md#onframe), а в серверной части Reflex-модуля — [`Scheduler:OnTick(callback)`](../../api/Scheduler.md#ontick).

<a id="2-result"></a>
## 2. Что реализуем

Готовый модуль будет:

- искать живого видимого противника в секторе перед прицелом;
- выбирать противника, расположенного ближе остальных к центру прицела;
- для `SniperRifle` и `Revolver` целиться в голову, а для другого оружия — в туловище;
- получать возможные траектории через [`FirearmItem:GetPredictedHits()`](../../api/Item.md#getpredictedhits);
- стрелять, только если не менее двух предсказанных траекторий попадают в выбранную цель;
- переключать режим клавишей `V` и запоминать его отдельно для каждого оружия;
- показывать текущий режим внизу экрана.

Порог в две успешные траектории выбран для примера. Чем он выше, тем дольше аим ждет подходящего разброса и тем реже стреляет.

<a id="4-server-aim"></a>
## 4. Серверная часть аима

Весь код этого раздела добавляется в `scripts/server.lua`.

### 4.1. Состояние и основные настройки

В файл `scripts/server.lua` добавьте первый блок: ссылки на локального агента, угол поиска, порог успешных траекторий и состояние, которое позже придет с клиента:

```lua
---@type Agent | nil
local LocalAgent = nil

local HALF_FOV_COS = math.cos(12 * math.pi / 180)
local MIN_SUCCESSFUL_PREDICTIONS = 2

local NetworkState = {
    SniperMode = false
}

Network:OnTableReceived(function(state)
    NetworkState = state
end)

local function IsAgentAlive(agent)
    return agent and agent.Health and agent.Health.IsAlive == true
end
```

`HALF_FOV_COS` задает, насколько близко к центру прицела должна находиться цель, чтобы аим начал ее рассматривать. Проще говоря, это радиус зоны поиска перед игроком, в пределах которого модуль ищет подходящего противника.

`NetworkState.SniperMode` пока равен `false`. Когда мы добавим клиентскую часть, сервер начнет получать актуальное значение через [`Network:OnTableReceived`](../../api/Network.md#ontablereceived). 

Жив ли агент, проверяется через [`Health.IsAlive`](../../api/Agent.md#health).

### 4.2. Поиск цели рядом с прицелом

В `scripts/server.lua` пропишем две функции:

```lua
local function GetAimDot(target, firePos)
    local toTarget = target.Aim.Position - firePos
    toTarget = toTarget:Normalize()

    return LocalAgent.Aim.Direction:Dot(toTarget)
end

local function FindBestTarget(firePos)
    local enemies = Agents:GetEnemies()
    local bestTarget = nil
    local bestDot = HALF_FOV_COS

    for i = 1, enemies.Length do
        local enemy = enemies[i]

        if IsAgentAlive(enemy) and enemy.IsVisible then
            local dot = GetAimDot(enemy, firePos)

            if dot > bestDot then
                bestDot = dot
                bestTarget = enemy
            end
        end
    end

    return bestTarget
end
```

[`Agents:GetEnemies()`](../../api/Agent.md#getenemies) возвращает массив противников относительно локальной команды. В Lua циклы по массивам API начинаются с `1`, поэтому перебор идет от `1` до `Length` включительно.

`GetAimDot` строит нормализованное направление к противнику и сравнивает его с [`Aim.Direction`](../../api/Agent.md#aim) через [`Vector3:Dot`](../../api/Structs.md#dot-2). Чем ближе результат к `1`, тем ближе цель к центру прицела. Проверка `enemy.IsVisible` не позволяет выбирать скрытых для локальной команды агентов.

### 4.3. Выбор хитбокса

Ниже в `scripts/server.lua` объявим функции для поиска хитбокса нужной части тела:

```lua
local function FindHitboxByBodyPart(target, bodyPart)
    local hitboxes = target:GetHitboxes()

    for i = 1, hitboxes.Length do
        local hitbox = hitboxes[i]

        if hitbox and hitbox.BodyPart == bodyPart then
            return hitbox
        end
    end

    return nil
end

local function GetAimHitbox(target)
    if NetworkState.SniperMode then
        return FindHitboxByBodyPart(target, EHitboxBodyPart.Head)
    end

    return FindHitboxByBodyPart(target, EHitboxBodyPart.Body)
        or FindHitboxByBodyPart(target, EHitboxBodyPart.Head)
end
```

[`Agent:GetHitboxes()`](../../api/Agent.md#gethitboxes) возвращает хитбоксы агента, а [`Hitbox.BodyPart`](../../api/Agent.md#hitbox) указывает, к какой части тела относится каждый из них.

В снайперском режиме функция возвращает только голову. В обычном режиме сначала ищет туловище, а если такого хитбокса нет — использует голову как запасной вариант.

<a id="5-predicted-hits"></a>
## 5. Как работают предсказанные выстрелы

### 5.1. Механика предсказания

Разброс не позволяет заранее описать будущий выстрел одной линией. Поэтому сервер каждый тик берет текущие [`Aim.Position`](../../api/Agent.md#aim), [`Aim.Direction`](../../api/Agent.md#aim) и неточность оружия, после чего рассчитывает несколько случайных траекторий возможного выстрела. В текущей реализации рассчитывается десять вариантов, но в коде лучше использовать `Length`, а не фиксировать это число вручную.

[`FirearmItem:GetPredictedHits()`](../../api/Item.md#getpredictedhits) возвращает `Array<Array<HitscanHit>>`:

- внешний массив содержит возможные траектории;
- каждый вложенный массив содержит последовательность попаданий одной траектории;
- одно попадание описывается объектом [`HitscanHit`](../../api/Item.md#hitscanhit);
- если пуля проходит сквозь поверхность, в той же траектории могут находиться следующие попадания после прострела.

Когда оружие действительно стреляет, сервер выбирает одну из заранее рассчитанных траекторий. Поэтому нельзя узнать единственную будущую точку попадания или выбрать конкретную траекторию. Зато можно оценить шанс: например, `2` успешных варианта из `10` означают, что цель пересекают два возможных направления выстрела.

У каждого [`HitscanHit`](../../api/Item.md#hitscanhit) также есть `EntryPoint`, `EntryPower`, `ExitPower` и `HasExited`. Через них более сложный аим может учитывать точку попадания и оставшуюся после прострела мощность. В учебном варианте достаточно самого факта пересечения хитбокса противника.

### 5.2. Подсчет успешных траекторий

Также в `scripts/server.lua` пропишем функцию, которая просматривает все попадания каждой траектории:

```lua
local function CountPredictedHitsOnTarget(firearm, target)
    local predictedShots = firearm:GetPredictedHits()
    local successfulShots = 0

    for shotIndex = 1, predictedShots.Length do
        local hits = predictedShots[shotIndex]

        for hitIndex = 1, hits.Length do
            local hit = hits[hitIndex]
            local hitbox = hit.Hitbox

            if hitbox and hitbox.Agent == target then
                successfulShots = successfulShots + 1
                break
            end
        end
    end

    return successfulShots
end
```

У [`HitscanHit.Hitbox`](../../api/Item.md#hitscanhit) может быть значение `nil`, например при попадании в геометрию карты. Если хитбокс есть, [`Hitbox.Agent`](../../api/Agent.md#hitbox) позволяет проверить его владельца.

Мы просматриваем весь вложенный массив, а не только первое попадание: так засчитывается и цель, находящаяся за простреливаемой поверхностью. После первого попадания в выбранного противника выполняется `break`, чтобы одна траектория учитывалась только один раз.

Оба цикла идут от `1` до `Length`: внешний перебирает предсказанные траектории, внутренний — попадания внутри одной траектории.

### 5.3. Серверный тик

Все вспомогательные функции готовы. В конец `scripts/server.lua` не забудем основной обработчик:

```lua
local function Tick()
    LocalAgent = Agents:GetLocalAgent()

    if not IsAgentAlive(LocalAgent) then
        return
    end

    local currentItem = LocalAgent.Inventory.CurrentItem

    if not currentItem or not currentItem.IsFirearm then
        LocalAgent.Aim:ResetAimTarget()
        return
    end

    local firearm = currentItem.AsFirearmItem
    local firePos = LocalAgent.Aim.Position
    local target = FindBestTarget(firePos)

    if not target then
        LocalAgent.Aim:ResetAimTarget()
        return
    end

    local hitbox = GetAimHitbox(target)

    if not hitbox then
        LocalAgent.Aim:ResetAimTarget()
        return
    end

    LocalAgent.Aim:SetAimTarget(hitbox.Position, target)

    local successfulShots = CountPredictedHitsOnTarget(firearm, target)
    local canFire = successfulShots >= MIN_SUCCESSFUL_PREDICTIONS
        and firearm.HasAmmo
        and not firearm.IsReloading

    AgentInput:SetButtonState(EInputButton.Fire, canFire)
end

Scheduler:OnTick(Tick)
```

На каждом серверном тике код:

1. получает локального агента через [`Agents:GetLocalAgent()`](../../api/Agent.md#getlocalagent);
2. берет [`Inventory.CurrentItem`](../../api/Agent.md#inventory) и преобразует огнестрельный предмет через [`Item.AsFirearmItem`](../../api/Item.md#item);
3. выбирает цель и хитбокс;
4. задает точку прицеливания через [`Aim:SetAimTarget`](../../api/Agent.md#setaimtarget);
5. считает успешные предсказанные траектории;
6. устанавливает состояние кнопки огня через [`AgentInput:SetButtonState`](../../api/Agent.md#setbuttonstate): нажимает, если достигнут порог и оружие готово стрелять, иначе отпускает.

Если подходящей цели или оружия нет, [`Aim:ResetAimTarget()`](../../api/Agent.md#resetaimtarget) возвращает управление прицелом игроку.

<a id="6-client"></a>
## 6. Клиентские настройки

Теперь настроим `scripts/main.lua`.

### 6.1. Клавиша переключения

В корне модуля создайте файл `inputs.json` и запишите в него:

```json
{
  "Actions": [
    {
      "Name": "ToggleSniperMode",
      "Type": "Button",
      "Binding": {
        "Path": "<Keyboard>/v"
      }
    }
  ]
}
```

Собственные действия модуля объявляются в `inputs.json`, а затем находятся по имени через [`InputActions:FindAction`](../../api/InputAction.md#findaction).
Общее описание формата и всех полей: [Tech.md / Файл inputs.json](./5.Tech.md#файл-inputsjson).

### 6.2. Клиентское состояние

В начало файла `scripts/main.lua` добавьте:

```lua
---@type FirearmItem | nil
local CurrentFirearm = nil

local ToggleSniperModeAction = nil
local NetworkState = {
    SniperMode = false
}

local function GetWeaponName(firearm)
    return string.gsub(firearm.Name, " ", "")
end

local function GetDefaultSniperMode(weaponName)
    return weaponName == "SniperRifle" or weaponName == "Revolver"
end
```

`CurrentFirearm` хранит текущее оружие. Пробелы удаляются из [`Item.Name`](../../api/Item.md#item), чтобы получить стабильный ключ для настроек. Для снайперской винтовки и револьвера режим головы включен по умолчанию.

### 6.3. Отправка и сохранение режима

Теперь добавим в `scripts/main.lua` функции, которые будут хранить выбранный режим отдельно для каждого оружия, восстанавливать его при переключении и отправлять актуальное состояние на сервер:

```lua
local function SendNetworkState()
    Network:SendTable(NetworkState)
end

local function SaveSniperModeForWeapon()
    if not CurrentFirearm then
        return
    end

    if not Storage.Weapons then
        Storage.Weapons = {}
    end

    local weaponName = GetWeaponName(CurrentFirearm)
    Storage.Weapons[weaponName] = NetworkState.SniperMode
end

local function LoadSniperModeForWeapon()
    if not CurrentFirearm then
        return
    end

    local weaponName = GetWeaponName(CurrentFirearm)
    local savedMode = Storage.Weapons and Storage.Weapons[weaponName]

    if savedMode ~= nil then
        NetworkState.SniperMode = savedMode
    else
        NetworkState.SniperMode = GetDefaultSniperMode(weaponName)
    end

    SendNetworkState()
end

local function ToggleSniperMode()
    if not CurrentFirearm then
        return
    end

    NetworkState.SniperMode = not NetworkState.SniperMode
    SaveSniperModeForWeapon()
    SendNetworkState()
end
```

`SaveSniperModeForWeapon()` записывает текущее значение `SniperMode` в [`Storage`](../../api/Storage.md#storage) под именем активного оружия, а `LoadSniperModeForWeapon()` читает это значение обратно. Если для оружия сохранения еще нет, используется режим по умолчанию из `GetDefaultSniperMode()`.

Функция `ToggleSniperMode()` нужна для ручного переключения: она меняет текущее состояние, сохраняет его и сразу вызывает `SendNetworkState()`. Эта функция отправляет на сервер `NetworkState`.

[`Storage`](../../api/Storage.md#storage) загружается автоматически при старте модуля и сохраняется при его отключении.

### 6.4. Отслеживание оружия

Еще в `scripts/main.lua` будет проверка смены предмета:

```lua
local function CheckFirearmChanged(localAgent)
    local currentItem = localAgent.Inventory.CurrentItem

    if currentItem and currentItem.IsFirearm then
        local firearm = currentItem.AsFirearmItem

        if not CurrentFirearm or firearm.Name ~= CurrentFirearm.Name then
            CurrentFirearm = firearm
            return true
        end
    elseif CurrentFirearm then
        CurrentFirearm = nil
        return true
    end

    return false
end
```

Функция возвращает `true`, только когда оружие действительно изменилось. Благодаря этому чтение `Storage` и отправка таблицы происходят при переключении предмета, а не каждый кадр.

### 6.5. Текст внизу экрана

В файл `scripts/main.lua` ниже предыдущих функций добавьте функцию отрисовки:

```lua
local function DrawSniperMode()
    if not CurrentFirearm then
        return
    end

    local text = "Sniper: off"

    if NetworkState.SniperMode then
        text = "Sniper: on"
    end

    ImGui:DrawText(
        text,
        Rect.new((Screen.Width * 0.5) - 100, Screen.Height - 80, 200, 30),
        20,
        Color.new(1.0, 1.0, 1.0, 1.0),
        TextAnchor.MiddleCenter)
end
```

[`ImGui:DrawText`](../../api/ImGui.md#drawtext) рисует текст в заданном [`Rect`](../../api/Structs.md#rect). Координаты рассчитываются от размеров [`Screen`](../../api/Environment.md#screen), поэтому надпись остается по центру при разном разрешении.

### 6.6. Клиентский кадр и подписки

В конец `scripts/main.lua` последний блок:

```lua
local function Tick()
    local localAgent = Agents:GetLocalAgent()

    if not localAgent or not localAgent.Health.IsAlive then
        return
    end

    if CheckFirearmChanged(localAgent) and CurrentFirearm then
        LoadSniperModeForWeapon()
    end

    DrawSniperMode()
end

ToggleSniperModeAction = InputActions:FindAction("ToggleSniperMode")
ToggleSniperModeAction:OnPerformed(ToggleSniperMode)
Scheduler:OnFrame(Tick)
```

[`InputAction:OnPerformed`](../../api/InputAction.md#onperformed) вызывает переключение режима по нажатию `V`. 
[`Scheduler:OnFrame`](../../api/Scheduler.md#onframe) проверяет оружие и рисует подпись каждый клиентский кадр.

Модуль готов: клиент хранит выбранный режим и передает его серверу, сервер выбирает цель и нажимает огонь только при достаточном числе подходящих траекторий. 

Готовые файлы примера лежат здесь: [Basic Reflex](../../../modules/Basic%20Reflex/).
