<a id="module-folder-structure"></a>
### Структура папки модуля

В корневой директории модуля могут находиться следующие файлы:

- `module.json` - основной файл с информацией о модуле (обязательный)
- `scripts/main.lua` - код, выполняющийся на стороне клиента (обязательный)
- `scripts/server.lua` - код, выполняющийся на сервере
- `config.json` - пользовательские настройки модуля
- `inputs.json` - пользовательские клавиши модуля
- `localization.csv` - таблица с переводами на разные языки

Также в директории модуля могут находиться необязательные папки с ресурсами:

- `audio/` - папка для звуковых файлов, поддерживаемый формат: `wav`
- `images/` - папка для файлов изображений, поддерживаемый формат: `png`
- `scripts/` - папка для файлов скриптов, поддерживаемый формат: `lua`
- `ui/` - папка для файлов UI, поддерживаемые форматы: `uxml`, `uss`

<a id="module-tags"></a>
### Теги модуля

В `module.json` у модуля есть поле `Tags`. Это массив тегов, который используется для группировки модулей по назначению и для предупреждений о пересечении функций.

Пример:

```json
{
  "Tags": ["Crosshair", "Notifications"]
}
```

У модуля может:

- не быть тегов
- быть один тег
- быть несколько тегов

Если тегов нет, модуль просто попадает в группу без тегов. Если тегов несколько, игра считает, что модуль относится сразу к нескольким категориям.

Доступные теги:

- `Minimap` - модули миникарты
- `PingMarks` - модули меток и пингов
- `OverheadLabels` - подписи и элементы над объектами
- `Crosshair` - прицелы и связанные с ними HUD-элементы
- `Health` - отображение здоровья
- `Notifications` - отображение уведомлений на экране
- `MatchStatus` - статус матча, раунда и игровой фазы
- `CombatReport` - боевой отчет
- `Scoreboard` - таблица счета
- `Loadout` - экипировка и информация о снаряжении
- `BuyMenu` - меню покупки
- `GrenadePreview` - предпросмотр гранат и траекторий
- `Chat` - чат
- `ThreatIndicator` - индикаторы гранат и направления опасности
- `KillFeed` - лента убийств
- `Spectator` - интерфейс наблюдателя
- `DebugInfo` - отладочная информация

### Конфликты тегов

Если одновременно активны два или более модуля с одним и тем же тегом, игра помечает их как конфликтующие. Это не блокировка: такие модули могут быть запущены одновременно.

Важно понимать, что конфликт тегов означает наложение функциональности. Например, два модуля с тегом `Crosshair` могут одновременно рисовать свой прицел, а два модуля с тегом `Notifications` - одновременно выводить похожие уведомления.

То есть конфликты тегов влияют в первую очередь на интерфейс и поведение модулей: предупреждают, что несколько модулей пытаются делать одну и ту же задачу. Обычные теги не ограничивают запуск модуля автоматически.

<a id="reflex-flag"></a>
### Флаг Reflex

`Reflex` - отдельный флаг `IsReflex` в `module.json`.

Пример:

```json
{
  "IsReflex": true,
  "Tags": []
}
```

Модуль с таким флагом отличается от обычного тем, что у него есть серверная часть в файле `scripts/server.lua`. Когда игрок заходит на сервер, игра берет код из этого файла на клиенте и отправляет его на сервер для выполнения.

Для Reflex-модулей действует отдельное ограничение: одновременно может быть запущен только один такой модуль. Это поведение не связано с тегами и работает отдельно от системы конфликтов тегов.

### Лимиты времени выполнения

Во время первичной инициализации файла `main.lua` модулю отводится 5 секунд. Если этот лимит будет превышен, модуль отключится до следующего перезапуска.

Также действуют лимиты времени выполнения за один кадр клиента и за один тик сервера. Клиентские модули ограничены `200 ms` за один кадр. Это огромный лимит, который помогает только от полного зависания игры: если в него упереться, то игра будет работать в 5 кадров в секунду. У серверных модулей ограничение строже: `1 ms` на 1 тик сервера.

При достижении лимита модуль приостанавливает выполнение, и продолжает его с того же место на следующем кадре или тике.
